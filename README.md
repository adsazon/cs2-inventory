# CS2 Inventory Value

Сервис на FastAPI для учёта инвентаря CS2. Позволяет добавлять и удалять предметы (полностью или поштучно), а также считать общую стоимость с учётом комиссии торговой площадки.

## Установка и запуск

Клонируйте репозиторий и перейдите в папку:

    git clone https://github.com/adsazon/cs2-inventory.git
    cd cs2-inventory

Создайте виртуальное окружение и установите зависимости:

    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements-dev.txt

Запуск для обычной работы (без автоперезагрузки):

    python -m uvicorn app_final:app --host 0.0.0.0 --port 8000

Для разработки (с автоперезагрузкой при изменении кода) используйте команду `python -m uvicorn app_final:app --reload`. Остановка сервера — `Ctrl+C`.

После запуска доступны:
- Swagger UI: `http://127.0.0.1:8000/docs`
- Проверка здоровья: `http://127.0.0.1:8000/health`
- Версия: `http://127.0.0.1:8000/version`

## Переменные окружения

Настройки читаются при старте. Если переменная не задана или содержит ошибку, сервис пишет `WARNING` в лог и использует значение по умолчанию.

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `APP_NAME` | `CS2 Inventory Value` | Название в документации |
| `DEFAULT_COMMISSION_PCT` | `15.0` | Комиссия площадки в % (0–100) |
| `MAX_ITEMS` | `50` | Лимит уникальных позиций в инвентаре |

Пример кастомного запуска:

    export APP_NAME="My Inventory" DEFAULT_COMMISSION_PCT=10 MAX_ITEMS=100
    python -m uvicorn app_final:app --host 0.0.0.0 --port 8000

Образец настроек лежит в `.env.example`. Файл `.env` в git не попадает.

## Маршруты API

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| `GET` | `/health` | Проверка работоспособности |
| `GET` | `/version` | Версия приложения |
| `GET` | `/inventory` | Посмотреть весь инвентарь |
| `GET` | `/inventory/total` | Стоимость с комиссией (параметр `commission`) |
| `GET` | `/inventory/{item_name}` | Информация о конкретном предмете |
| `POST` | `/inventory/{item_name}` | Добавить предмет (или увеличить количество) |
| `DELETE` | `/inventory/{item_name}` | Удалить предмет полностью |
| `DELETE` | `/inventory/{item_name}/{qty}` | Удалить N штук предмета |

**Пример добавления** (2 штуки AK-47 по 35.0):

    curl -X POST http://127.0.0.1:8000/inventory/ak47 \
      -H "Content-Type: application/json" \
      -d '{"price": 35.0, "qty": 2}'

**Пример расчёта стоимости** (комиссия 10%):

    curl "http://127.0.0.1:8000/inventory/total?commission=10"

## Тесты

Запуск локально:

    python -m pytest -v

В проекте 23 теста: базовые операции, частичное удаление, обработка ошибок (404, 422, 400), валидация цен и лимитов.

## Логи и диагностика

Логи пишутся в `stdout` (где запущен uvicorn). Формат: `время уровень логгер сообщение`. Логируются запуск, добавление/удаление предметов, расчёты и ошибки.

| Проблема | Решение |
| :--- | :--- |
| `No module named uvicorn` | Активируйте `.venv`: `source .venv/bin/activate` и установите зависимости |
| `Address already in use` | Порт 8000 занят. Остановите старый сервер (`Ctrl+C`) или используйте `--port 8001` |
| `422 Unprocessable Entity` | Проверьте JSON: `price > 0`, `qty >= 1`, имя без спецсимволов |
| `404 Not Found` | Предмета нет в инвентаре. Проверьте `GET /inventory` |
| `WARNING: Invalid ...` в логах | В env-переменной опечатка. Сервис работает на дефолтных значениях |

**Хранение данных:** инвентарь живёт в памяти процесса. При перезапуске сервера данные очищаются.

## CI (GitHub Actions)

Файл `.github/workflows/ci.yml` запускается при `push` и `pull_request`. Он ставит зависимости, запускает тесты и, если они зелёные, сохраняет файлы приложения в artifact `app-files`. Результаты — на вкладке **Actions**.
